# 架构铁律：机端自管环境，后端只管跨机的事

> 2026-10-01 立（用户口述，作为硬约束）
> 一句话：**机端存在的原因是"现场"**——截图/识别/操作要求低延迟、必须在设备隔壁；
> 后端与机端**不一定是同一台机器**，所以凡是"这台机器自己的事"，一律由机端自己处理。

---

## 1. 分工（谁负责什么）

| 事 | 归属 | 说明 |
|---|---|---|
| MAA 本体（CLI + 核心 + 资源） | **机端** | 自己查最新版、自己下载安装（`fleet setup`）；不依赖任何旧安装 |
| 本机环境（模拟器路径、adb、实例列表、端口） | **机端** | 自己探测；端口/索引漂了自己认（`fleet doctor`） |
| 账号表 / 任务文件 / profile | **机端** | 自己从本地数据生成（`fleet gen`），缺失即重建 |
| 设备与任务生命周期（起停机、发车、判定、自愈） | **机端** | 现场操作，后端不参与 |
| 排班（谁先跑、并发多少） | **机端**（按后端策略） | 本机资源闸门由机端自己判断；跨机队的口径由后端下发 |
| 机队台账 / 指令下发 / 审计 / 对外 API / UI | **后端** | 只做"机端做不了"的跨机事务；**不碰**机端本地路径与文件 |
| 加入机队所需的地址与密钥 | 外部输入一次 | `fleet setup -center <URL> -token <KEY>`（相当于 join），之后全自动 |

## 2. 自举链（一台全新机器）

```
① 下 fleet.exe（本项目 Release）
② fleet setup -center http://<后端>:8790 -token <KEY>
     ├ 探测环境（MuMu/adb/实例）
     ├ 装 maa-cli + core + resource 到 <项目> 内
     ├ 写默认 runner.json / node conf.json
     └ 生成账号表与任务文件（fleet gen）
③ fleet runner（或由开机自启拉起）
     └ 队列 → 起机 → 跑 → 停机 → 上报后端
```

**验收标准**：一台干净机器上只允许两条人工输入——`fleet.exe` 文件、后端地址+密钥；其余全自动。
