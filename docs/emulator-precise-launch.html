精准开启指定模拟器（MuMuManager）实测：主 MRFZ-0000 · MuMu12 · 2026-09-30

目标：给任意实例（如 l-5=idx34、l-7=idx52）做「精准冷启 + 就绪验证」，全程只碰指定那台，不误动其他。

① 标准命令

"E:\MuMu Player 12\nx_main\MuMuManager.exe" control --vmindex <idx> launch
  • 路径实测：E:\MuMu Player 12\nx_main\MuMuManager.exe（旧文档写 x_main\ 是错的）。
  • 参数：control --vmindex 34 launch（-v 34 等价写法也支持）。
  • shutdown：同前缀 control --vmindex 34 shutdown。
  • 查询：info -v 34 返回 JSON（index/name/是否启动/磁盘等）。

③ 启动后的「就绪验证」三件套（权威判据，不信 info 状态面）

# 1) VMM 进程在（权威） Get-CimInstance Win32_Process -Filter "Name='MuMuVMMHeadless.exe'" | Where-Object { $_.CommandLine -match 'MuMuPlayer-12\.0-34' } # 2) 监听口（需现查，端点会漂：16384+32*idx 只是线索） Get-NetTCPConnection -OwningProcess <VMM_pid> -State Listen # 3) adb connect 后 device + boot_completed "E:\MuMu Player 12\shell\adb.exe" connect 127.0.0.1:<port> "E:\MuMu Player 12\shell\adb.exe" -s 127.0.0.1:<port> shell getprop sys.boot_completed # =1

重要：MuMuManager info -v 的进程状态面在主机上可能"假死/报假"——每次决策都以 VMM 进程 + adb 实测为准（多份审计验证）。

④ 跨 SSH 宿主持久化（避免误判"没启动"）

  • 用 Win32_Process.Create（PowerShell）或 schtasks 一次性任务拉起，不要用 Start-Process——它会随 SSH 会话结束被带走。
  • 同理适用于 maa-cli 长跑进程（肉鸽队实操已用 schtasks）。
# PowerShell 跨会话启动模板 $r = Invoke-CimMethod -ClassName Win32_Process -MethodName Create -Arguments @{ CommandLine = '"E:\MuMu Player 12\nx_main\MuMuManager.exe" control --vmindex 34 launch' } $r.ProcessId # 立即返回 pid，进程与 SSH 会话解耦

⑤ 与 maa-cli 刷肉的对接（l-5 目标流程）

# (1) MuMuManager 启动 idx34 # (2) 就绪三件套通过 # (3) 本机 maa-cli 经 SSH 隧道控制（本机 16520 <-> 主机 16452 实例的当前 adb 口） MAA_STATE_DIR=...state_l5 D:\MAA-CLI\dist\maa.exe --batch run rogue_mizuki_l5 -a 127.0.0.1:<本机口> # 注意：l-5 有"其他主题进行中"锁时，先跑界园一把到整局结算退出（Failed/Abandon 均可解锁）， # 再切水月；锁不会因关游戏消失，必须那局真正打完。
