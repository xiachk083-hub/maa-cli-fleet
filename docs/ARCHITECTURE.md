# 三层一体（机端 / 后端 / 前端）· 结构设计（ARCHITECTURE）

> 2026-10-01 · 状态：**结构定稿讨论稿**（尚未实现；先留结构，代码之后再写）
> 一句话：机队系统 = **三个组件构成的"一台系统"**——组件是分开的进程、**可以跑在不同机器上**，
> 之间用"内部地址"互相寻址；三者合起来才是一个整体（类似分布式计算里的 中心 + 工作节点）。

---

## 0. 总体形状

```
  ┌──────────────┐      HTTP/WS（内部地址）      ┌──────────────┐
  │  ③ 前端       │  ───────────────────────────► │  ② 后端       │
  │ console 暂缓  │   （只依赖中心，不知道执行器）  │  center      │
  └──────────────┘                               └──────┬───────┘
                                                        │ 心跳/上报（上行）
                                                        │ 指令/查询（下行）
                                                        │ 内部地址：执行器主动连中心
                                                 ┌──────▼───────┐
                                                 │   ① 机端      │   ×  N 台
                                                 │  node/executor│
                                                 │  （贴着模拟器） │
                                                 └──────────────┘
```

**关键性质**
- **进程分离**：三件东西各自独立启动/停止/升级，互不要求同机。
- **可跨机**：每个组件只认"对方的内部地址"（配置项）；同一台机器上也行（地址=127.0.0.1）。
- **合为一体**：中心把执行器抽象掉后，对外（前端/CLI/Agent）呈现为"一个机队系统"。
- **地址即配置**：所有内部地址、端口、token 都不写死在代码里。

## 1. 组件定义

### ① 机端（node / executor）—— 跑在目标机上，每台机器一个（可 N 个）
**位置**：贴着实机（今天 = 主机 MRFZ-0000；将来可多台）。
**职责**
- 在本机驱动模拟器与 maa-cli（起/停任务、adb、模拟器管理）；
- 运行**本地循环与安全逻辑**（游戏日补齐、理智时钟、卡死自愈、设备级恢复）；
- 向中心**上报**：心跳、机台状态（任务/理智/worker/最近动作/异常）、事件；
- 接受中心**指令**并回执（含 dry-run 计划与拒绝原因）。

**边界（不做的事）**
- 不渲染界面；不做全局策略裁决（全局节奏/批量操作由中心表达为指令）；
- **中心不可达时仍自我保全**（本地自愈继续跑，缓存事件待补报）——安全逻辑不下放给中心。

**现有资产**：`ops/rogue_cli_ops.ps1`（今天的成果，零重写）+ 一个薄代理层（上报/接令）。

### ② 后端（center / 中心服务）—— 常驻，全局一个
**位置**：任意常开机器（默认本机；也可换到主机）。
**职责**
- **注册表**：目标机清单（id / 角色 / 能力 / 任务模板映射）；
- **状态聚合**：把各执行器的心跳与状态拼成"机队实时视图"（含历史）；
- **指令路由**：把用户/自动化/Agent 的命令转成"对某台执行器的指令"，跟踪回执；
- **审计**：全量动作与事件（一份事实源）；
- **对外 API**：给前端/CLI/Agent 用；把执行器抽象为"机台"。
- **租约/互斥**：同一机台同一时刻只允许一个控制者（中心层锁 + 执行器本地看守，双保险）。

**边界**：中心**不直接**碰模拟器/maa-cli。

### ③ 前端（console）—— ⏸ 暂缓，全局一个
**位置**：浏览器（任一台可访问中心的机器）。
**职责**：机队看板（机台卡片/状态/日志/操作按钮）；**只依赖中心 API**，对执行器无感。
**状态**：**本轮不做**（功能未完善）；中心 API 定型后随时接入。

## 2. 组件间接口（内部协议）

| 方向 | 谁主动 | 载体 | 内容（草案） |
|---|---|---|---|
| 执行器 → 中心 | 执行器 | HTTP POST（+WS 可选） | `register` / `heartbeat` / `state` / `event`（含 action 回执） |
| 中心 → 执行器 | **执行器拉** | 长轮询/短轮询 HTTP | `poll_commands` → 指令队列（cmd、参数、deadline） |
| 前端 → 中心 | 前端 | REST + WS | `GET /fleet` / `GET /machine/<id>` / `POST /command` / 事件流 |
| 人/CLI → 中心 | 人 | 同 REST（或中心本地 CLI） | 同上 |

**设计取舍（写清理由，可改）**
- **执行器只做"出站连接"**：目标机不开放监听端口 → 免 NAT/防火墙烦恼；
- 中心不可达 = 执行器继续本地自治（自愈照跑），事件缓存待补报；
- 所有"写动作"在指令层保留 `apply` 语义（dry-run 计划可先行返回）。

**寻址与安全**
- 每个执行器有稳定 `node_id`（建议 `host-xxxx` / `l-x`）；中心记录其最近来源地址与版本；
- 认证：中心 ↔ 执行器共享 token（或双向 mTLS 备选）；中心 ↔ 前端 token；
- 传输：内网（Tailscale 100.x / LAN）；跨网段时套 SSH 隧道（同"远程网关·通过SSH"那套心法）。

## 3. 数据与状态归属

| 数据 | 归属 | 说明 |
|---|---|---|
| 机台台账（清单/角色/主题） | **中心** | 中心是事实源（可下发给执行器做校验） |
| 机台实时状态（任务/理智/worker） | 执行器产生 → 中心聚合 | 执行器本地持有最新；中心持有视图+历史 |
| 动作/事件审计 | 中心（汇聚） | 执行器本地也留一份（today 的 ops 日志） |
| 任务文件 / 连接配置 | 执行器本机 | 属于"驻场资产"（今天已是项目内自包含） |
| 租约/互斥 | 中心（下发）+ 执行器（本地看守） | 双保险，防双控 |

## 4. 部署形态（同一套结构，三种摆法）

| 形态 | 后端 | 机端 | 前端 | 场景 |
|---|---|---|---|---|
| **单机** | 本机 | 本机（127.0.0.1） | 暂缓 | 今天的最小闭环 / 开发联调 |
| **主从（目标形态）** | 本机（常开） | **主机（机端驻场）** | 暂缓 | 目标机免隧道（模拟器就在执行器本机） |
| **多节点** | 任一台 | 多台（每台一机端） | 任一台 | 多机队扩展 |

> 形态切换只改"内部地址"配置，不动结构。

**当前控制权**：仍是 `local-desktop`（隧道模式）驱动全队；`host-mrfz0000` 只上报不改状态。
**下一步（需批准，属"现场操作"）**：单台试迁——对某台机停掉本机 worker/隧道，改由主机机端驱动（daily/rogue），验证真结算后再逐台迁。

**坑（已踩，写死在这里）**：
- 目标机常驻进程必须用 **WMI `Win32_Process Create`** 拉起（`Start-Process` 的子进程随 ssh 会话结束被杀）；
- `MuMuManager info -v all` **不含** `adb_port`，端口要 `info -v <idx>` 逐个查；
- GitHub 仓库转公开后 codeload/archive 有**分钟级传播延迟**，期间 404（raw 先通）；
- 私有仓 `codeload`/`archive` 一律 404（无鉴权路径）→ 要么转公开、要么带 token。
